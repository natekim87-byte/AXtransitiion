어디서부터 시작할까요?

STEP 1 · 각자 15분

회사의 AI 수준 진단

5개 영역, 25개 문항에 1~5점을 매깁니다. 문항마다 1·3·5점의 예시가 있으니 우리 회사와 가장 가까운 쪽을 고르세요. 점수는 바로 계산되고, 결과는 STEP 2에 자동으로 반영됩니다.

적용 대상
  • AX 담당자 (진단 주관, 결과 취합)
  • 경영기획·전략 담당
  • IT·데이터 담당
  • 현업 부서장: 영업, 마케팅, MD, CS, SCM, 매장운영
각자 따로 진행하며, 1명만 해도 결과가 나옵니다.

진단 가이드

사용 방법

  1. A~E 탭을 차례로 열고, 탭 위의 판단 기준을 먼저 읽습니다.
  2. 문항마다 1·3·5점 예시를 보고 점수를 누릅니다. 중간이면 2점이나 4점을 고릅니다.
  3. 오른쪽에서 레벨과 병목 영역을 확인합니다.
  4. 역할을 고르고 결과 복사를 눌러 AX 담당자에게 메신저나 메일로 보냅니다.

채점 원칙

  • 근거가 있는 것만 점수로 인정합니다. 문서, 예산, 시스템 화면으로 보여줄 수 없다면 한 단계 낮게 줍니다.
  • 계획이 아니라 현재 상태로 채점합니다. "내년에 할 예정"은 1점입니다.
  • 잘 모르는 문항은 2점을 주고, AX 담당자에게 확인할 문항으로 표시해 둡니다.
  • 내 부서가 아니라 회사 전체를 기준으로 봅니다.

결과 해석

  • 레벨은 종합 점수를 반올림한 값입니다. 2.5~3.4점이면 L3입니다.
  • 가장 낮은 영역보다 두 단계 이상 높은 레벨은 나오지 않습니다. 예를 들어 평균이 L4여도 거버넌스가 L2면 L3로 조정됩니다.
  • 병목 영역은 다른 영역보다 0.5점 이상 낮은 영역입니다. 확산 전에 먼저 보강하세요.
  • 여러 명의 결과에서 1.5점 이상 차이 나는 문항은 워크숍 1회차의 토론 주제로 삼으세요.
STEP 2 · 워크숍 1회차

성숙도에 따른 프로세스 적용 레벨 산정

업무를 AI에 얼마나 맡길지를 네 단계로 나눕니다. 회사 레벨이 넘을 수 없는 한도를 정하고, 그 안에서 업무별 조건에 따라 실제 레벨이 정해집니다.

성숙도 × 적용 레벨 매핑

성숙도권장 적용 레벨최대 허용지금 할 일아직 하지 말 것

업무별 적용 레벨 정하기

부서에서 AI를 적용할 업무를 하나 정하고 아래 질문에 위에서부터 답하세요. 처음 "아니오"가 나오기 직전 레벨이 그 업무의 레벨입니다.

P1담당자가 AI 도구로 초안·요약·번역 도움을 받을 수 있는 업무인가?대부분의 사무 업무가 해당됩니다.예 → P1 가능
P2팀이 같은 방식으로 반복하는 업무이고, 필요한 자료를 AI에 넣을 수 있는가?예: 매주 쓰는 리포트, 정해진 양식의 제안서예 → P2 가능
P3판단 규칙이 분명하고, AI가 틀려도 피해가 작거나 사람이 바로 잡을 수 있는가?예: 문의 유형 분류, 송장 데이터 입력. 가격·계약·인사 평가는 해당하지 않습니다.예 → P3 가능
P4여러 시스템을 오가는 판단을 맡길 만큼 데이터 연동과 통제 장치가 갖춰졌는가?예: 수요예측을 보고 AI가 발주까지 실행예 → P4 가능
마지막으로 회사 레벨의 최대 허용을 확인하세요. 업무 조건이 P3여도 회사가 L2라면 지금은 P2까지만 적용합니다. 사용 가이드라인, IT 지원, 결과 모니터링이 없는 상태에서 자동화를 돌리면 오류가 생겼을 때 수습할 체계가 없기 때문입니다. 회사 레벨이 오르면 같은 업무를 한 단계 올리면 됩니다.

STEP 3 · 워크숍 2회차

우선 적용 업무 선정

후보 업무를 넓게 찾은 뒤, 스코어카드로 첫 과제 3개를 고릅니다. 좋은 후보는 주 1회 이상 반복되고, 담당자가 주 2시간 이상 쓰고, 자료가 이미 있고, 사람이 결과를 검토할 수 있는 업무입니다.

    적용 예시

    주간 매출 브리핑: Tableau 데이터에 질문해서 인사이트 얻기

    1원천 데이터POS 매출 · 이커머스 주문 · B2B 수주(ERP) · 프로모션 일정 · 재고(WMS)
    →
    2Tableau 게시 데이터 원본"주간매출_통합" 하나로 게시. 기존 대시보드가 쓰던 원본을 그대로 씀
    →
    3VizQL Data Service게시된 데이터 원본을 차트 없이 JSON 쿼리로 조회하는 Tableau API
    →
    4Tableau MCP 서버VDS와 Pulse를 LLM이 쓸 수 있는 도구로 열어 줌
    ⇄
    5LLM (Claude 등)질문을 이해하고 필요한 도구를 골라 조회한 뒤 결과를 해석
    Tableau Pulse 주간 매출, 객단가, 온라인 전환율, B2B 수주액을 지표로 등록하면 평소 범위를 벗어난 변화와 그 원인 후보를 자동으로 찾습니다. LLM은 MCP를 통해 이 결과를 출발점으로 삼습니다.

    ③ 월요일 오전, 질문으로 브리핑 만들기 예시 데이터

    지난주 매출 어땠어? 크게 움직인 곳이 있으면 알려줘.
    Pulse 인사이트 · 주간 매출query-datasource · 지역 × 채널, 전주·전년
    지난주 전사 매출은 48.2억 원으로 전주 대비 −3.4%, 전년 대비 −1.2%입니다. Pulse가 평소 범위를 벗어난 변화로 잡은 곳은 수도권 매장(−13.8%, −2.9억 원) 한 곳입니다. 온라인(+4.2%)과 지방 매장, B2B는 소폭 늘어 하락을 일부 상쇄했습니다.
    수도권 매장은 왜 빠졌어? 카테고리별로 봐줘.
    query-datasource · 수도권 매장 × 카테고리query-datasource · 프로모션
    하락분 2.9억 원 중 2.1억 원(72%)이 아웃도어입니다. 전년 같은 주에는 수도권 아웃도어 20% 할인전이 있었고 올해는 없었습니다. 가설 전년 프로모션의 기저효과가 주원인으로 보입니다.
    결품 영향은 없었어?
    query-datasource · 재고 (수도권 아웃도어)
    수도권 아웃도어 상위 20개 상품 중 3개가 4일 이상 결품이었습니다. 평소 판매 속도로 추정하면 약 0.4억 원을 놓쳤고, 아웃도어 하락의 약 20%에 해당합니다.
    점장 회의용으로 5줄 요약하고, 이번 주에 확인할 것도 적어줘.
    1. 전사 매출 48.2억 원, 전주 대비 −3.4%
    2. 하락은 수도권 매장(−2.9억 원)에 집중, 온라인은 +4.2%
    3. 수도권 하락의 72%가 아웃도어: 전년 할인전 기저효과(가설)
    4. 아웃도어 3개 상품 결품으로 약 0.4억 원 손실 추정
    5. B2B 수주는 평소 범위
    이번 주 확인할 것: 결품 3개 상품 입고 일정, 수도권 아웃도어 프로모션 재개 여부

    LLM이 매번 어떤 도구를 불렀는지 표시되므로, 숫자의 출처를 Tableau에서 다시 확인할 수 있습니다.

    ④ 바뀌는 것

    지금적용 후
    브리핑 작성매주 4시간: 엑셀 취합, 피벗, 문장 작성질문 4개, 약 20분
    추가 질문BI팀에 대시보드 수정 요청, 1~2주 대기그 자리에서 바로 질문
    이상 변화 발견회의에서 누군가 눈치챌 때Pulse가 먼저 알려 줌
    새로운 분석개발 요청 후 대기질문과 프롬프트를 바꾸면 끝

    팔란티어 같은 FDE 없이, 원하는 AI 인사이트를 직접 만듭니다

    팔란티어 방식은 FDE(Forward Deployed Engineer)가 고객사에 들어와 데이터 모델과 분석 앱을 맞춤으로 만들어 줍니다. 강력하지만 엔지니어를 투입하는 기간과 비용이 들고, 새로운 질문이 생기면 다시 엔지니어에게 요청해야 합니다.

    이 방식에서는 이미 쓰고 있는 Tableau 게시 데이터 원본이 데이터 모델 역할을 하고, 공식 MCP 서버가 연결을 맡습니다. 현업은 질문만 바꾸면 원하는 분석을 바로 얻습니다. 분석을 맞춤으로 바꾸는 주체가 외부 엔지니어에서 현업으로 옮겨 오는 것이 핵심입니다.

    FDE 방식Tableau + MCP + LLM
    누가 만드나외부 엔지니어가 상주하며 구축사내 데이터 담당 + AX 담당
    시작까지엔지니어 투입과 구축 기간 필요약 2주
    새 질문이 생기면엔지니어에게 요청현업이 바로 질문
    쓰는 데이터새 플랫폼으로 통합이미 쓰는 Tableau 데이터 원본

    여러 시스템에 흩어진 데이터를 묶어 운영 의사결정까지 자동으로 실행해야 한다면 FDE형 플랫폼이 맞을 수 있습니다. 매출 브리핑처럼 분석과 인사이트가 목적이라면 이 방식으로 충분합니다.

    도입 전에 확인하세요. Tableau MCP 서버는 Tableau가 공개한 오픈소스 프로젝트로 기능이 계속 바뀌고 있습니다. VDS와 Pulse를 쓸 수 있는지는 라이선스와 배포 형태(Tableau Cloud, Tableau Server)에 따라 다릅니다. 조회 결과가 LLM으로 전달되므로, 입력 데이터가 학습에 쓰이지 않는 기업용 LLM을 쓰세요.

    참고: Tableau VizQL Data Service · Tableau MCP (GitHub) · 대화 속 수치는 설명을 위한 예시입니다.
